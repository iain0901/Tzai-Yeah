# 載耶 2026｜工作人員操作手冊

這份手冊配合實體 NFC 票卡使用。卡片上的 `030` 代表 30 級；每張卡的辨識方式是後台產生的獨立網址，以及卡套上另寫的流水號。票卡會在活動前發放。

## 先認識三種資料

| 資料 | 用途 | 交給誰 |
| --- | --- | --- |
| 卡套流水號，例如 `001` | 讓工作人員快速找卡、核對發放紀錄 | 可寫在卡套上 |
| 專屬卡片網址 | 寫入 NFC；感應後讀取該卡對應的活動內容 | 持卡者；不要公開整份清單 |
| 私人認領碼 | 持卡者登入後認領自己的個人頁編輯權 | 單獨交給本人，不寫入 NFC，也不貼在卡套外面 |

專屬卡片網址可重複開啟，活動前、中、後都使用同一個連結，不是用過就失效的一次性網址。參加者感應 NFC 後已經進到自己的頁面，網站不會再要求他感應一次。

流水號不是密碼，卡片網址也不是編輯權限。任何取得卡片網址的人都可能查看該卡的公開內容；認領碼才用來把參加者與登入帳號連結。一般參加者不需要取得後台權限。

## 第一次準備

1. 先確認要長期使用的正式網站網址。不要把本機的 `localhost`、`127.0.0.1` 或暫時預覽網址寫入正式票卡。
2. 以本機管理員帳號開啟 `/admin`，確認後台可用及正式資料庫已完成初始化。首次帳密由自架初始化產生，存放於 `secrets/admin-login.txt`；一般新註冊帳號不會自動取得管理權。部署與帳號設定見 [自架手冊](SELF-HOSTING.md)。
3. 設定活動日期、入場時間、開始與結束時間、場地和文字。預設為 2026 年 11 月 21 日、15:30 入場、16:00～22:00、國立清華大學教育館。
4. 先建立所有組別，填好組名、集合位置和必要提醒。這些資料稍後會出現在持卡者的分組畫面。
5. 產生正式卡片網址，再匯入參加者名單並綁定卡片。可另準備幾張備用卡；每張備用卡也必須有不同的網址。
6. 活動階段先保持「活動前」，分組揭曉保持關閉。

實際發卡前，請先完成文末的正式環境檢查。開發環境內的示範資料不能代替正式名單。

「建立專屬網址」輸入的是卡片**總數**，不是這次新增數。例如已有 150 張，想補 5 張備用卡就填 `155`；既有 150 個網址會保持不變。

## 寫入 NFC 與卡套編號

1. 在「NFC 小卡」按「匯出 NFC 網址清單」。每一列的流水號與網址是一對，不能只複製第一列給所有卡片。
2. 在卡套標示對應流水號，例如 `001`。同一時間只拿出一張卡和它的卡套，避免交叉裝錯。
3. 使用能寫入 NFC 網址的工具，把該列完整網址寫入卡片的 URL／URI 紀錄。此網站產生網址，並不直接操作手機 NFC 寫入。
4. 將卡片離開手機後重新感應，確認開啟的是正式網域，並核對網頁顯示的流水號與卡套。
5. 核對後台中該卡綁定的參加者，再記錄已寫入、已測試、已發放的狀態。若網站沒有這三個獨立欄位，可在工作人員的發卡清單記錄，請勿拿「報到」代替。
6. 換另一支手機抽測；依現場需求準備 QR Code 或由工作人員協助開啟網址的備援方式。

修改分組、活動階段、預告影片、回顧內容及個人連結，都不需要重新寫 NFC。網址的網域與路徑仍須持續維護，卡面日期不會讓網址自動到期。

寫入工具可能提供不可逆的永久鎖定功能。只有在正式網址與逐張感應都確認後，才考慮使用；卡片能否鎖定、是否可還原，以實際卡片和寫入工具為準。

## 匯入參加者名單

在後台先建立組別並產生卡片，再到「參加者名單」→「匯入 CSV」→「下載空白範本」。使用 UTF-8 CSV，第一列為欄位名稱：

```csv
姓名,家別,組別,卡號
林同學,第一家,暖燈組,001
陳同學,第二家,拼圖組,002
```

- `姓名` 必填；`家別`、`組別`、`卡號` 可先留白，再於後台補齊。
- `組別` 使用後台已建立的完整組名或組別 ID；避免多個組別使用相同名稱。
- `卡號` 指卡套流水號，與卡面 `030` 無關。一張卡只能綁定一位參加者。
- 試算表若把 `001` 變成 `1`，匯入預覽會嘗試對應三位數卡號；仍請檢查最後配對結果。
- 每次最多匯入 500 位。檔案中的重複卡號、不存在的組別、錯誤欄位及空白姓名應先修正。
- 姓名不是唯一識別碼；同名者需要依家別和發卡紀錄辨識。

先看匯入預覽，確認列數和錯誤訊息，再按「確認匯入」。匯入後抽查姓名、家別、分組及卡號。完全相同的一批資料重送會避免重複新增；但匯入功能不是更新功能，改過內容的 CSV 仍可能新增參加者。名單變動請編輯既有參加者。

「匯出名單」與「下載現場備用名單」是供核對的報表，欄位不同於匯入範本，不能直接當作完整資料庫備份還原。

## 人工分組：先編輯，再發布

工作人員調整的是分組草稿。持卡者看到的是已發布版本，因此改到一半的安排不應立即出現在前台。

1. 在組別及參加者管理中完成分組、集合地點和提醒文字。
2. 檢查所有需要分組的人是否已指定組別、所有需要發卡的人是否已綁卡。
3. 檢查每組人數，並由另一位工作人員交叉核對關鍵安排。
4. 在「人工分組」按「確認並發布分組」並確認發布，核對發布時間與版本有更新。只要仍有參加者尚未分組，系統就會阻止發布。
5. 若有臨時換組，修改後還要再次發布。連線正常且前台開啟時，約 15 秒內會更新；不必要求參加者再次感應。

「發布分組」和「開放揭曉」是兩件事。可以先發布正確名單，仍讓活動前的持卡者只看到預告和活動資訊。

若要移除組別，到「人工分組」→「編輯」→「移除這個組別」並確認。原組員會在草稿中變成尚未分組；已發布版本暫時保留。先替這些人安排新組別，再重新發布。

## 三個活動階段

| 階段 | 工作人員設定 | 持卡者體驗 |
| --- | --- | --- |
| 活動前 | 活動前；揭曉關閉 | 主畫面是活動介紹與邀請動畫；有影片時可主動播放直式預告 |
| 活動中，尚未開放 | 活動中；揭曉關閉 | 等待揭曉的內容，不顯示組別 |
| 活動中，已開放 | 活動中；揭曉開啟；已有已發布分組 | 主畫面顯示這張卡的組別、集合位置與小提醒 |
| 活動後 | 活動後 | 主畫面是耶誕紀念畫面與回顧文字，按鈕連到外部活動相簿 |

階段與「開放分組揭曉」由主辦在「活動總覽」切換，按下後即儲存，不會依日期自動切換。連線正常且前台開啟時，約 15 秒內會讀取更新；回到頁面也會重新確認。三個階段改的是同一專屬網址的主畫面，無須重寫 NFC，也不需要參加者再感應一次。

發布分組、切到「活動中」、開放「分組揭曉」三個步驟都完成後，才會公布個別組別。修改後，保留一個已開啟的持卡者頁面驗證自動更新。活動已開始但卡片未綁人或尚未完成分組時，應回後台修正。

## 加上直式 YouTube 預告

影片尚未完成時，將預告影片欄位留白，網站使用活動資訊動畫。

影片就緒後，在「頁面內容」→「YouTube 影片網址」貼上單支影片的分享網址，再按「儲存頁面內容」。網站接受常見的 `youtube.com/watch`、`youtu.be`、`youtube.com/shorts` 與嵌入網址，儲存時會驗證影片 ID。

使用者可以點擊播放，活動資訊仍保留在頁面中。請實際測試影片的分享與嵌入權限；只貼上網址不會更改 YouTube 的影片權限。直式影片也應在一般手機上檢查字幕、播放按鈕及返回資訊區是否容易操作。

## 發放私人認領碼

認領的用途是取得活動後個人頁的編輯權，與掃卡查看分組、工作人員報到分開處理。

1. 確認參加者和卡片綁定正確，到「參加者名單」選擇該人的「個人頁管理」，再按「產生一次性認領碼」。
2. 將碼單獨交給本人，例如發卡時另附折好的紙條，或透過原本已核對的聯絡方式提供。
3. 持卡者從自己的卡片頁進入管理流程，登入後輸入認領碼。
4. 認領成功後，以該登入帳號管理個人內容。不要把工作人員帳號留在借給參加者操作的手機上。

認領碼只顯示一次，有效期限 30 天；完成認領後立即失效。重新產生會使舊碼失效；已認領者須勾選解除既有帳號綁定，才會重設擁有者。每位參加者在一個小時時段內最多嘗試 8 次，連續輸錯時請先核對碼，不要持續重試。

認領碼不是共用活動密碼，也不要整份貼進群組。重新發碼或解除原擁有者前，先核對本人；卡片遺失並不代表拾獲者可以取得編輯權。

## 活動後回顧與個人連結

只需要在「頁面內容」貼上**活動相簿連結**，再填一句回顧文字。網站會提供完整的耶誕紀念畫面，參加者點按按鈕後前往你既有的照片服務；不需要把整本相簿搬進網站，也不需要逐張上傳。請先用一般參加者身分確認相簿可開啟，再切到「活動後」。

未設定相簿連結時，紀念畫面仍會出現，並顯示回憶整理中的訊息。可選用一張公開 HTTPS 圖片作為封面；不填就使用聖誕插畫。若舊版已有多張照片，第一張用作封面，其餘設定仍保留，前台不做照片輪播。這些進階設定收在「選填：回顧封面照片」中。

持卡者認領後，仍可從「小屋」→「我的紀念小卡」編輯名稱、簡介與個人 HTTPS 連結。個人連結由持卡者或朋友主動點按開啟，不會在進站時自動跳走，也不會蓋過活動回顧與相簿入口。即使舊資料曾選擇直接開啟連結，進站也會先顯示活動階段的主畫面。

在原卡片網址後加上 `?edit=1` 可直接進入需要登入驗證的編輯流程，例如 `https://正式網域/t/卡片代碼?edit=1`。查看活動、組別與相簿不需要先認領個人頁。

## 報到、換卡與遺失處理

「領卡」、「開啟過網頁」、「認領個人頁」和「已報到」是不同狀態。工作人員應依現場核對結果操作報到，不以參加者曾掃卡作為報到依據。

換卡時，先核對參加者，在「NFC 小卡」停用遺失卡，再到「參加者名單」→「編輯」→「配對小卡」選擇備用卡。替換配對時系統也會停用原卡；同一位參加者的個人頁、擁有者與分組關係會保留。測試新卡及舊卡狀態，核對分組，若同時改了組別就再次發布。不要把其他人已在使用的卡直接拿來替換。

停用卡片會影響舊網址的服務，但無法抹除曾被截圖或另外保存的資訊。實體卡與網址可被轉交，因此本網站的分組顯示不能代替現場的持票人核對。

## 離線備援與現場流程

活動當天開場前，在「活動總覽」按「下載現場備用名單」，核對卡號、姓名、家別、已發布組別、集合位置及報到時間。把檔案保存到現場可離線讀取的工作人員裝置；必要時另備紙本。一般「匯出名單」使用的是分組草稿，現場請用已發布版本的備用名單。

離線匯出是當下快照，不會隨後台更新。臨時換組或換卡後重新匯出，清楚標示版本或時間。內含參加者資料及卡片網址的檔案不要公開分享。

網路暫時不可用時，工作人員依離線名單協助找到組別及集合位置，另外記錄人工報到結果。恢復連線後再補回後台；離線名單不會自動同步。

## 本機與正式環境的差異

| 項目 | 本機開發／預覽 | 正式網站 |
| --- | --- | --- |
| 網址 | 通常是 `127.0.0.1` 或 `localhost`，只供開發驗證 | 寫入卡片前確認的長期 HTTPS 網址 |
| 資料庫 | 本機 SQLite，預設放在 `data/tzai.sqlite` | 自己伺服器上的 SQLite；Docker 存在持久化 named volume |
| 登入 | 與正式站相同的本機帳號與密碼驗證 | 使用自己的管理員／會員帳號，無須 ChatGPT 登入 |
| 資料搬移 | 測試卡、名單及分組留在指定的資料庫 | 發布程式不等於搬移資料；使用備份還原或特定匯入功能 |
| 更新 | `npm run dev` 供開發測試 | 重新建置與啟動，啟動時自動套用未執行的遷移 |

資料庫結構變更與名單資料不同：遷移建立或調整資料表；匯入才是新增活動參加者。此專案的結構遷移位於 `drizzle/`，自架版本會在開啟資料庫時套用未執行的遷移。不要把測試認領碼、個人資料或本機環境變數一起打包公開。

管理員權限儲存在自己的 SQLite 帳號資料中；一般註冊不會取得後台權限。舊版 `ADMIN_EMAILS`、Sites 身分標頭與模擬帳號不再是這個版本的登入方式。首次管理員帳密、工作階段密鑰與資料備份都應私人保管。

### 正式網站存取權限

自架前台可直接公開閱讀，後台與個人頁編輯仍需驗證。若反向代理另外設有密碼或來源限制，訪客仍可能在進入網站前被擋下。工作人員自己能開啟，不代表 150 位參加者都能開啟。

正式發卡前，請用沒有工作人員權限的手機或瀏覽器，依真實參加者流程感應測試。若活動需要任何持卡者直接閱讀資訊，正式主機必須允許這個閱讀範圍；後台和個人編輯仍各自驗證權限。不要為了讓大家看前台而授予後台管理權。

## 發卡前與開場前檢查

完整檢查表位於 `tests/acceptance-checklist.md`。至少完成：

- 正式網域、一般訪客權限、正式資料庫及工作人員帳號都驗證過。
- 每張卡的 NFC 網址、卡套流水號與參加者配對一致。
- 沒有把認領碼寫進 NFC 或混進公開名單。
- 分組已發布，集合位置正確，活動前無法提前取得分組資料。
- 活動資訊在動畫結束後仍可閱讀；影片尚未上架時沒有空白播放框。
- 現場網路與至少兩支手機實測完成，離線名單已存妥。
- 指定一位工作人員負責切換階段，另一位負責核對前台結果。
